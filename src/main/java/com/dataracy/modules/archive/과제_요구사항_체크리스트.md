# 백엔드 개발자 과제 요구사항 체크리스트

## ✅ 완료된 항목

### 1. 데이터 모델

- ✅ MeetingRoom: 회의실 정보 (이름, 수용인원, 시간당 요금)
- ✅ User: 사용자 정보
- ✅ Reservation: 예약 정보 (예약시간, 결제상태, 총 결제금액)
- ✅ Payment: 결제 정보 (결제사 타입, 결제 금액, 결제 상태, 외부 결제 ID)
- ❌ **PaymentProvider**: 결제사 정보 (결제사명, API 엔드포인트, 인증정보) - **구현되지 않음**

### 2. 필수 API 엔드포인트

- ✅ GET /meeting-rooms
- ✅ 예약 생성/조회/취소 등 CRUD 기능
- ✅ POST /reservations/{id}/payment
- ✅ GET /payments/{paymentId}/status
- ⚠️ POST /webhooks/payments/{provider} - **부분 구현** (현재는 `/webhooks/payments/toss`, `/webhooks/payments/kakao`로 분리됨)

### 3. 비즈니스 규칙

- ✅ 예약 시간 중복 방지 (동일 회의실)
- ✅ 시작 시간 < 종료 시간
- ✅ 정시(00분) 또는 30분 단위로만 예약 가능
- ✅ 요청 파라미터 유효성 검사(Validation) 필수

### 4. 결제 시스템 추상화

- ✅ Strategy Pattern 구현
- ✅ 다중 결제사 통합 (Toss, Kakao)
- ✅ 공통 데이터 모델 변환 (PaymentStatus 열거형)
- ⚠️ **결제사 수 부족**: 요구사항은 A사(신용카드), B사(간편결제), C사(가상계좌) 3개인데 현재는 2개만 구현

### 5. 동시성 제어

- ✅ Deadlock 해결 로직 (Redisson 분산 락)
- ✅ 결제 처리 중 예약 상태 관리 (PENDING → COMPLETED → CONFIRMED)

### 6. 기술 요구사항

- ✅ Java 17
- ✅ Spring Boot 3.x (3.3.11)
- ✅ MySQL (Docker 컨테이너)
- ✅ Spring Data JPA
- ✅ Swagger (OpenAPI 3.0)
- ✅ Docker + Docker Compose
- ✅ JUnit 5

### 7. Docker 환경

- ✅ docker-compose.yml 포함
- ✅ Dockerfile 포함
- ✅ docker-compose up 한 번의 명령으로 전체 실행 가능
- ✅ 애플리케이션 + 데이터베이스 + Mock 결제서버 통합 구성

### 8. 테스트

- ✅ 핵심 비즈니스 로직 테스트
- ✅ 결제 추상화 서비스 단위 테스트
- ✅ Mock 결제 API 테스트 환경 구성
- ✅ 통합 테스트 작성

## ❌ 부족한 항목 (우선순위별)

### 🔴 **높은 우선순위 (필수)**

#### 1. PaymentProvider 엔티티 구현

**요구사항**:

- PaymentProvider: 결제사 정보 (결제사명, API 엔드포인트, 인증정보)

**현재 상태**:

- 구현되지 않음
- 결제사 정보가 하드코딩되어 있음

**작업 필요**:

- PaymentProvider 엔티티 생성
- 결제사 정보를 DB에서 관리
- 결제사별 API 엔드포인트 및 인증정보 저장

#### 2. 결제사 3개 구현 (현재 2개)

**요구사항**:

- A사 결제사: 신용카드 결제 (CardPaymentAPI)
- B사 결제사: 간편결제 (SimplePaymentAPI)
- C사 결제사: 가상계좌 결제 (VirtualAccountAPI)

**현재 상태**:

- Toss (간편결제로 추정)
- Kakao (간편결제로 추정)
- 신용카드 전용 결제사 없음
- 가상계좌 결제사 없음

**작업 필요**:

- 신용카드 전용 결제 게이트웨이 추가
- 가상계좌 결제 게이트웨이 추가
- 또는 기존 결제사를 요구사항에 맞게 재구성

#### 3. 웹훅 API 경로 수정

**요구사항**:

- POST /webhooks/payments/{provider} (동적 경로)

**현재 상태**:

- POST /webhooks/payments/toss
- POST /webhooks/payments/kakao (고정 경로)

**작업 필요**:

- PathVariable로 provider를 받는 단일 엔드포인트로 통합
- Provider별로 분기 처리
